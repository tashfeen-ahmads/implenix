<Answer q="What are LLM, RAG, and MCP AI agents?">
An LLM AI agent uses a large language model to reason, plan, and act. A RAG AI agent also looks facts up in your own documents before answering. An MCP AI agent reaches tools and data through the Model Context Protocol, an open standard. They are layers, not rivals: most production agents use all three.
</Answer>

I get asked to explain RAG, LLM, and MCP by operators who have
been told by three different vendors that theirs is the
"best" version of one of these things. All three terms describe
real technical architecture, but they answer different
questions. The LLM decides what to do. RAG decides what the agent
knows about your business. MCP decides how the agent reaches your
systems. This is the explainer from someone who ships these
systems into phone lines, not a technical paper.

Each of the three gets its own section below with a short answer
up top, so jump to the one you searched for.

## What is an LLM AI agent?

<Answer q="What is an LLM AI agent?">
An LLM AI agent is software that uses a large language model (GPT, Claude, Gemini, Llama, Mistral and similar) to decide what to do next, then does it. A plain LLM only writes a reply. An LLM agent runs that reply through a loop: read the situation, reason, pick an action such as a tool call, observe the result, and repeat until the goal is met.
</Answer>

That reason-then-act loop was described clearly in the
[ReAct paper](https://arxiv.org/abs/2210.03629) (Yao et al.,
2022), which showed language models interleaving reasoning steps
with actions like searching an API. Almost every modern agent,
including the voice agents I deploy, is a variation on it.

### The parts of an LLM agent

- **The model.** The reasoning engine. Model choice affects
  quality, speed, and running cost.
- **Instructions.** The system prompt that defines the role,
  scope, tone, and rules. On a phone line this is where most of
  the quality comes from, which is why I wrote a separate guide
  on [writing prompts for AI voice agents](/blog/how-to-write-prompts-for-ai-voice-agents).
- **Tools.** Functions the agent can call: check a calendar,
  create a CRM record, transfer a call.
- **Memory.** What it keeps within a conversation (and sometimes
  across conversations), such as the caller's name and the
  problem they described.
- **Guardrails.** Constraints on what it may say and do. Raw
  model output is not production-ready without them.

### LLM vs LLM agent

An LLM answers a prompt and stops. An LLM agent uses the model's
output to take the next step in the world. Ask a plain LLM
"is Tuesday at 10 free?" and it will guess. Ask an LLM agent and
it checks the calendar. Calling something an "LLM agent" in 2026
is a bit like calling a car an "engine-powered vehicle":
accurate, but it tells you nothing about whether it will do your
job.

## What is a RAG AI agent?

<Answer q="What is a RAG AI agent?">
A RAG AI agent is an LLM agent with a retrieval step. Before it answers, it searches a knowledge base you control (policies, service menus, FAQs, past tickets), pulls the most relevant passages, and gives them to the model so the answer is grounded in your documents instead of the model's general training data.
</Answer>

RAG stands for retrieval-augmented generation. The term comes
from a [2020 paper by Patrick Lewis and colleagues](https://arxiv.org/abs/2005.11401)
at Facebook AI Research, UCL, and NYU, which paired a language
model with a searchable index of documents.

### How RAG works, step by step

1. **Prepare.** Your documents are split into small chunks.
2. **Index.** Each chunk is turned into an embedding (a numeric
   fingerprint of its meaning) and stored in a vector database.
3. **Retrieve.** When a question comes in, the agent searches for
   the chunks closest in meaning to the question.
4. **Generate.** The model writes its answer using those chunks,
   and can cite which document each fact came from.

Why this matters for a business: the base model has a training
cutoff and has never seen your policies, your service area, or
your insurance list. RAG is how the agent answers "do you accept
Delta Dental for kids?" with your answer instead of a plausible
guess.

### Traditional RAG vs agentic RAG

Traditional RAG retrieves once, every time, and answers. Agentic
RAG lets the agent decide whether it needs to look something up,
which source to search, and whether to search again if the first
results were thin. On a phone line that difference shows up as
speed: an agent that retrieves on every turn adds delay to
simple questions that never needed a lookup.

### RAG vs fine-tuning

Fine-tuning changes the model itself by training it on examples.
RAG leaves the model alone and changes what it reads at answer
time. For business facts that change (hours, prices, policies,
staff), RAG is almost always the right call, because you update a
document instead of retraining a model.

### When RAG fits and when it does not

RAG is the right architecture when:
- The agent needs business-specific information to answer.
- That information changes over time.
- You need answers traceable to a source document.

RAG is overkill when:
- The job is procedural (booking, intake, transfer) and needs no
  reference lookup.
- The data already sits behind an API the agent can query
  directly, such as live availability.

The most common RAG failure I see is not the technology. It is a
stale or contradictory knowledge base: two versions of the
cancellation policy, or last year's holiday hours. The agent
retrieves faithfully from bad source material.

## What is an MCP AI agent?

<Answer q="What is an MCP AI agent?">
An MCP AI agent is an agent that connects to outside tools and data through the Model Context Protocol, an open standard for plugging AI applications into business systems. Instead of custom integration code for every tool, the agent talks to "MCP servers" that expose a system's actions and data in one shared format.
</Answer>

Anthropic [introduced MCP in November 2024](https://www.anthropic.com/news/model-context-protocol)
as an open standard, and in December 2025
[donated it to the Agentic AI Foundation](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)
under the Linux Foundation, so it is no longer controlled by a
single vendor. Other major AI providers have since adopted it.

### How MCP works

- **Host.** The AI application the user interacts with (a chat
  app, an IDE, a voice agent runtime).
- **Client.** The connector inside the host that speaks MCP.
- **Server.** A small service in front of a system (a CRM, a
  calendar, a file store) that exposes what the agent may use.

An MCP server can offer three kinds of things: **tools** (actions
the agent can take, like "create appointment"), **resources**
(data it can read, like a customer record), and **prompts**
(reusable templates). The agent discovers what is available and
decides which tool to call, with what inputs, in what order.

Analogy: MCP is to AI agents what USB was to peripherals. It is a
wiring standard, not a brain.

### MCP vs an API

MCP does not replace APIs. An MCP server usually sits on top of a
system's existing API and describes it in a way any MCP-capable
agent can discover and use. The benefit is portability: build the
connector once, use it from any compatible agent. The cost is one
more layer to secure and maintain.

### MCP vs A2A

MCP connects an agent to tools and data. Google's Agent2Agent
(A2A) protocol connects agents to other agents. They solve
different problems and are often used together. I cover A2A in
[can AI agents talk to each other](/blog/multi-agent-systems-crypto-agi).

### The security question with MCP

Every MCP server you connect is a new set of permissions. Two
risks matter: an agent being tricked by instructions hidden in
content it reads (prompt injection), and servers that grant more
access than the job needs. Give each agent the narrowest set of
tools that does the job, prefer read-only where that is enough,
and log every call.

### When MCP matters to you

MCP is worth caring about when:
- You expect to switch AI vendors and want integrations to move
  with you.
- You have many internal tools to expose to agents.
- Your engineering team is building custom agent workflows.

MCP is not worth caring about when:
- Your vendor already handles all your integrations natively.
- You are a small business buying a turnkey phone agent, where
  the question is "does it write to my calendar and CRM reliably,"
  not "which protocol does it use."

## What operators actually need to ask vendors

Rather than "is your agent RAG or LLM or MCP" (the answer is
almost always "yes to all"), ask these:

1. **How does the agent answer questions about my specific
   business?** Good answer: through a documented knowledge base
   that we can update as your business changes. Bad answer:
   through the model's training data.
2. **How does the agent connect to my CRM, calendar, and other
   systems?** Good answer: documented API or MCP integrations that
   write records reliably and log every write. Bad answer:
   scraping or manual re-entry.
3. **What happens when the model gets something wrong?** Good
   answer: answers are constrained by retrieval and structured
   tool calls, and uncertain cases go to a human. Bad answer:
   "our model does not hallucinate." All models do to some degree.
4. **Can you swap the underlying LLM without breaking my
   deployment?** Good answer: yes, the architecture is
   model-agnostic. Bad answer: we are locked to one model vendor.

Those four questions test the substance behind whatever labels
the vendor uses. For the wider integration picture, see
[how AI agents plug into CRM, ERP, and BI systems](/blog/ai-agent-integration-crm-erp-bi).

## Common vendor misuse of these terms

- **"Ours is a RAG agent" as a differentiator.** Every serious
  vendor has retrieval. It is table stakes. Ask how the knowledge
  base is kept current.
- **"We support MCP" without explaining what that gets you.** Ask
  which systems have working MCP servers today and who maintains
  them.
- **"Our agent is more advanced because it uses [technique X]."**
  Ask what business outcome that technique improves. If the vendor
  cannot answer, it does not matter.

## When these architecture details actually matter to buy

- **You are building custom in-house.** Then you care deeply
  about all three.
- **You are evaluating enterprise-tier platforms.** Architecture
  affects portability and switching cost.
- **You need answers about complex proprietary information.**
  Retrieval quality becomes a real differentiator.
- **You operate in a regulated industry with audit
  requirements.** How the agent grounds its answers (RAG) and how
  it touches source-of-truth systems (MCP or otherwise) affects
  your compliance posture.

Otherwise, these are terms to recognize, not things to make a
purchase decision on.

## Frequently asked questions

**Is a RAG agent the same as a chatbot with a knowledge base?**
Close. A chatbot with a knowledge base retrieves and answers. A
RAG agent can also act on what it found, such as booking the
appointment after confirming the insurance is accepted.

**Who created MCP?**
Anthropic introduced the Model Context Protocol in November 2024
and later donated it to the Agentic AI Foundation under the Linux
Foundation. It is an open standard that many AI providers and
tool vendors now support.

**Is MCP going to replace custom API integrations?**
Partly, over time. Today, direct API integrations still cover
most small-business use cases. MCP mostly changes who writes the
connector and how reusable it is.

**Is an LLM agent the same as an AI agent?**
Effectively yes in 2026. Non-LLM agents (rule-based systems,
small task-specific models) still exist, but they are not what
most people mean by "AI agent" today. For the full taxonomy, see
[types of AI agents explained](/blog/types-of-ai-agents-explained).

**Do I need to know which LLM my agent uses?**
Not usually, unless you have specific requirements around speed,
data residency, or cost. Ask whether it can be swapped.

**What about voice-specific terms?**
Speech-to-text, text-to-speech, and turn-taking models sit around
the LLM, RAG, and MCP layers. For a voice agent, all of them run
together on every turn. Our glossary entry on
[voice AI](/glossary/voice-ai) covers those pieces.
